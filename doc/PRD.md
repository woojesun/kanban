## 2. 배경 및 목적

프로젝트 작업을 시각적으로 관리하기 위한 칸반 보드를 제공한다.
사용자는 카드를 세 가지 상태(To-Do / In Progress / Done)로 분류하고
드래그 앤 드롭으로 상태를 전환할 수 있어야 한다.

**현재(v1.0)** 는 인증 없이 동작하지만, **복수 사용자가 각자의 보드를 소유하는 구조**를 처음부터 전제하고 설계한다.
사용자 식별자(`userId`)를 데이터 모델과 저장 키에 포함하여, 추후 Supabase 인증을 붙일 때 구조 변경 없이 연동할 수 있어야 한다.

## 6. 다중 사용자 설계 원칙

v1.0부터 아래 원칙을 지켜 Supabase 연동 시 구조 변경을 최소화한다.

1. 모든 카드/컬럼 데이터에는 `userId` 필드가 포함된다.
2. localStorage 키는 `kanban-{userId}` 형식으로 사용자별로 분리한다.
3. 헤더에는 로그인 상태를 표시할 `.user-bar` 영역을 미리 배치한다.
4. 데이터 읽기/쓰기 함수는 `userId` 파라미터를 항상 받도록 설계한다.
5. v2.0에서 localStorage → Supabase DB로 교체할 때 함수 시그니처는 유지된다.
